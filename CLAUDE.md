# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this is

Leo's personal portfolio site — a from-scratch upgrade/redesign, separate from
the older `portfolio-site/` (static HTML/CSS/JS) sub-project elsewhere in the
workspace. Originally generated by [Lovable](https://lovable.dev), then
cloned locally (`git clone https://github.com/leosanga/portfolio-vercel`)
for direct editing with Claude Code.

**No longer connected to Lovable.** The Lovable sync banner, `.lovable/`
tracking dir, `@lovable.dev/vite-tanstack-config` vite wrapper, and the
Lovable-only error-reporting shim have all been removed — this repo is now a
plain TanStack Start app with no Lovable dependency. Hosting target: Vercel
(nitro preset `vercel` in `vite.config.ts`).

## Stack

- **React 19** + **TypeScript**, **Vite 8** (`vite dev`, not `vite.config`
  presets from CRA/Next)
- **TanStack Start** (`@tanstack/react-start`) + **TanStack Router**
  (file-based routing under `src/routes/`, route tree auto-generated into
  `src/routeTree.gen.ts` — don't hand-edit that file)
- **Tailwind CSS v4** (`@tailwindcss/vite` plugin, no separate `tailwind.config`
  in the classic v3 sense — check `src/styles.css` for `@theme`/tokens)
- **shadcn/ui** component primitives under `src/components/ui/` (Radix-based) —
  these are vendored/generated, treat as library code, not hand-rolled
- **Bun** is the package manager in practice (`bun.lock` present), though
  `package.json` scripts also work with npm/pnpm since they just shell out to
  `vite`. `bunfig.toml` present.

## Commands

```bash
bun install        # or npm i
bun run dev         # vite dev — served at http://localhost:8080 by default
bun run build        # production build
bun run preview       # preview the production build
bun run lint            # eslint .
bun run format           # prettier --write .
```

No test suite currently configured.

## Editing content

Almost all copy edits are in **`src/components/portfolio/data.ts`**:
`NAV_LINKS`, `COMPETENCIES`, `PROCESS_STEPS`, `PROJECTS`, `CONTACT`. Component
files just map over these arrays — check `data.ts` first before hunting
through JSX for text.

Section anchor ids (must stay in sync across `data.ts` `NAV_LINKS`, each
section's `<section id="...">`, and `useActiveSection`'s consumer in `Nav.tsx`):
`skills`, `approach`, `projects`, `contact`.

## Scrollspy behavior (`useActiveSection.ts`)

The header nav highlights a link when the corresponding section's bounding
box contains the vertical center of the viewport (`rect.top <= center &&
rect.bottom >= center`), computed on a `requestAnimationFrame`-throttled
scroll listener — not an `IntersectionObserver` ratio/threshold band. That
was deliberate: a fixed-percentage viewport band combined with
`intersectionRatio` thresholds silently breaks for sections whose height
differs a lot from the band (a short section can pass through unnoticed, a
tall section may never reach the ratio threshold). If you touch this hook,
keep the center-line/`getBoundingClientRect` approach rather than reverting
to a ratio-threshold `IntersectionObserver` — that bug was hit and fixed
twice already. No active link is shown when scrolled above the first section
(`active` starts as `""`, not defaulted to the first id).
