# Handoff: Lovable → Vercel migration

Date: 2026-08-15

> **STATUS: HISTORICAL — every step below is done, including the whole
> "Not done yet — next steps" list at the bottom.** Git identity is set, the
> stale history was wiped and re-initialised, `leosanga/portfolio-vercel`
> exists on GitHub again, and Vercel deploys `main` on push. Kept only as the
> record of *why* the Lovable wrapper, error shim, and vite config were removed
> the way they were. For the current state of the codebase read `CLAUDE.md`,
> not this file.

## What changed

This repo was originally generated by Lovable and cloned locally for direct
editing. It is now fully decoupled from Lovable and configured to deploy to
Vercel.

### Removed (Lovable-only)

- `.lovable/` — Lovable's own project tracking dir (`project.json`, plan doc)
- `AGENTS.md` — contained only the Lovable sync warning banner, nothing else
- `src/lib/lovable-error-reporting.ts` — posted errors to `window.__lovableEvents`,
  which only exists inside the Lovable editor preview iframe; no-op everywhere
  else. Its one call site (`ErrorComponent` in `src/routes/__root.tsx`) was
  removed along with the now-unused `useEffect` import.
- `@lovable.dev/vite-tanstack-config` — the vite config wrapper package
- `vite-tsconfig-paths` — separately dropped; Vite 8 provides the same
  behavior natively via `resolve.tsconfigPaths: true`, which is what
  `vite.config.ts` now uses

### `vite.config.ts` — full rewrite

The Lovable wrapper wasn't just cosmetic — it silently bundled the entire
plugin stack (Tailwind v4, TanStack Start, React, dev/build error loggers)
*and* set nitro's build target, defaulting to Cloudflare
(`defaultPreset: "cloudflare-module"`). Removing the package meant
hand-rolling that config. The new file wires up the same plugins directly
and sets `nitro({ preset: "vercel" })`.

Read `node_modules/@lovable.dev/vite-tanstack-config/dist/index.js` if you
ever need to see exactly what the old wrapper did by default (dev-only
plugins, sandbox detection, etc. — all irrelevant now, but that's where the
`importProtection` option on `tanstackStart(...)` in the new config was
copied from — it's a real feature, not Lovable-specific, so it was kept).

### Other cleanup

- `<head>` meta in `src/routes/__root.tsx` still said `"Lovable App"` /
  `@Lovable` — replaced with real portfolio metadata (title, description,
  author, og:title, og:description). Dropped the `twitter:site` tag since
  there's no real handle to put there.
- `README.md` rewritten off Lovable's template boilerplate.
- `.gitignore` — added `.vercel` (Vercel CLI/build output, must not be
  committed).
- `src/lib/error-capture.ts` and `error-page.ts` were *not* removed — despite
  living next to the Lovable error-reporting file, they're generic SSR error
  handling (h3 error unwrapping, a fallback error page) with no Lovable
  dependency.

## Build verification

`bun run build` was run after every structural change. Final state builds
clean and produces `.vercel/output/` in Vercel's Build Output API v3 format
(the format nitro's `vercel` preset targets directly — Vercel's platform
recognizes this automatically, no extra config needed). No env vars are
required at build or runtime (checked — nothing in `src/` reads
`process.env.*` or `import.meta.env.VITE_*`).

## GitHub repo deleted — start clean here

`leosanga/portfolio-vercel` was deleted on GitHub (confirmed gone via
`gh repo view` returning "Could not resolve to a Repository"). Reason: the
repo's commit history was entirely Lovable-era (`Lovable <noreply@lovable.dev>`,
`gpt-engineer-app[bot]`), and GitHub's Contributors list showed a third party
(`RennanLucas`) attributed via a verified-email match on one of those
commits — not fixable without rewriting history, and there was no history
worth keeping anyway (this was always a generated scaffold, not hand-written
commits). Deleting and starting over was simpler than rebasing/squashing.

**The local `.git` in this folder is now stale** — it still has the old
Lovable commit history and its `origin` remote points at a repo that no
longer exists. Local files/working tree are fine and up to date (everything
in this handoff already happened on disk); only the git history + remote
need to be redone.

## Not done yet — next steps (do these in order, next session)

1. **Set git identity** (nothing configured locally or globally —
   `git config user.name` / `user.email` are both currently empty):
   ```sh
   git config --global user.name "<your name>"
   git config --global user.email "<your email>"
   ```
2. **Wipe the stale history and start fresh:**
   ```sh
   rm -rf .git
   git init
   git add .
   git commit -m "Initial commit"
   ```
3. **Create the new GitHub repo and push:**
   ```sh
   gh repo create leosanga/portfolio-vercel --public --source=. --remote=origin --push
   ```
   (`--public` assumed — swap to `--private` if preferred. This single
   command creates the repo, sets `origin`, and pushes in one step.)
4. **Connect Vercel.** Dashboard method (recommended): vercel.com → sign in
   with GitHub → Add New Project → import `leosanga/portfolio-vercel`.
   Framework preset: **Other** (Vercel won't recognize "TanStack Start" by
   name). Build command: `bun run build` (or `npm run build`). Install
   command: `bun install`. Leave Output Directory on default — do **not**
   point it at `dist`; nitro's `vercel` preset already writes Vercel's own
   Build Output API structure to `.vercel/output`, which the platform
   detects automatically. No env vars needed.
   - Alternative: Vercel CLI (`npm i -g vercel`, `vercel login`,
     `vercel link`, `vercel --prod`) — not installed locally, and doesn't
     give you auto-deploy-on-push the way the dashboard/GitHub integration
     does.
5. Portfolio content work (copy, layout) is unrelated to this migration and
   was already in progress before this session — the working tree already
   has in-flight component edits (`Hero.tsx`, `Nav.tsx`, `data.ts`, etc.)
   that predate the Lovable removal. These'll just be part of the single
   fresh initial commit in step 2, nothing extra to do for them.
